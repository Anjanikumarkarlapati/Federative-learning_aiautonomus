# Repository analysis: FL-AV (Federative-learning_aiautonomus) for a patent-ready research paper

Scope: internal analysis of the local repo `/home/user/Federative-learning_aiautonomus` (branch `claude/elegant-darwin-5cnkqn`, HEAD `3b539ac`; every code/result file is identical to `ede06ed` of 2026-09-17, HEAD only adds unrelated "patient-level paper" notes). Analysis date 2026-10-08.

Citation convention: repository facts are cited as `path:line` (or the file/field name for data). Web facts carry an inline [Source](URL); web checks were limited to a few prior-art look-ups and were read at search-snippet level only. Items marked "(run)" were verified by me by executing the repo code in a scratch venv outside the repo (torch 2.14.1+cu130 wheel run on CPU, Python 3.13); nothing was written into the repo except this file. The 51 repo tests all pass in that environment (`pytest tests/ -q`: 51 passed in 36.8 s).

Bottom line up front:
1. The repo is a PyTorch **simulation** of federated training of a small multi-task perception net (700,485 parameters, verified) over a fleet of 50 simulated vehicles on **procedurally generated synthetic 32x32 scenes**. It is an integration of mostly known techniques (FedAvg, quality weighting, link-aware client selection, FedAvgM-style server momentum, FedNova, top-k + error feedback, pairwise-mask secure aggregation, DP-FedAvg with an RDP accountant). There is **no AI-agent/LLM/RL/"autonomous" software component**; "autonomous" means autonomous vehicles.
2. Patentable substance is thin: at best narrow combination/system claims. No concept has a clean, unambiguous prior-art gap, and the repo's own data shows **no synergy** (the combined algorithmic arm is worse than FedAvg in the R=30 study) and a **worse worst-client tail** for the proposed arm.
3. All results are **one seed, one synthetic fleet**; headline accuracy is a maximum over test-set rounds. Several claims in the README/docs do not match the code (details in Q5): FedNova is silently bypassed under the default secure aggregation (run), the "standard FedAvg" baseline does not use random selection (run), the fairness guard does not bound starvation (run), the committed `std_fedavg` arm was produced by older code than HEAD (fingerprint mismatch, run).
4. **Disclosure status:** the GitHub repo `Anjanikumarkarlapati/Federative-learning_aiautonomus` is **private** (GitHub API, 2026-10-08), created 2026-09-16T08:42:55Z, 0 forks/stars/releases/PRs, no public-visibility event in the retrievable event stream. No public disclosure was found. The `Claude-Session:` URLs in commit trailers and the PRD (not in repo) are open provenance/disclosure questions.

## Q1. What does the system do end to end (problem, data, models, federated algorithm, aggregation, selection, privacy/security, autonomy, evaluation)?

### Takeaway
FL-AV simulates a Road-Side-Unit (RSU) coordinating a fleet of vehicles that train one shared perception + trajectory model without sending raw data, only compressed model deltas plus three scalars (n_k, q_k, update norm). The server loop is FedAvg with (a) quality-weighted weights, (b) connectivity/region/fairness-aware selection, (c) server momentum, (d) optional FedNova step normalisation, (e) optional DP and pairwise-mask secure aggregation, (f) top-k+error-feedback uplink, fp16+gzip+CRC32 wire format and delta/multicast downlink. It is a spec-driven build ("PRD v1.0", which is **not** in the repo); there is no agentic/autonomous-decision component other than a threshold-feedback bandwidth controller.

### Cited Findings
**Problem and provenance**
- Goal: privacy-preserving collaborative training for connected/autonomous vehicles; "implementation follows PRD - FL Framework for Collaborative AV Training, v1.0 section by section" — `README.md:8-9`. The PRD file does not exist in the repo (`git ls-files`); the commit message of the first commit (`07986cc`, 2026-09-16 09:39:32 UTC) says "Full implementation of the FL-AV PRD v1.0".
- No agent/LLM/RL code: a grep for `agent|llm|autonom|blockchain|reinforcement|bandit|policy|gpt|claude|openai` over `*.py/*.yaml/*.txt/*.md` finds only the word "autonomous" in the README title/intro and "agent" in dataset comments (`fedav/config.py:21`, `fedav/data/adapters.py:60`); "blockchain contribution auditing" appears only as a roadmap item (`README.md:621`).

**Data (synthetic only)**
- `fedav/data/scenes.py:133-200` `render_scene`: 32x32x3 images with an object rectangle (class from shape/size/jittered colour), motion streak (speed/heading), lane-marking slant (yaw rate); 6 classes incl. background (`scenes.py:31`), 3 regions x 4 weathers (`:32-33`); ground truth = class, box (cx,cy,w,h), 6 future waypoints (x,y) from a constant-speed/constant-yaw-rate roll-out (`:191-199`).
- Non-IID fleet `fedav/data/federated.py:178-243`: label skew p_k ~ Dirichlet(alpha=0.4) (`:146-150`), quantity skew log-normal sigma=0.45 (`:153-160`), feature skew region = k mod 3, weather random (`:191-195`), 12% chance a vehicle is "de-calibrated" with 25-45% label corruption (`:194,197`) and extra blur/brightness drift (`scenes.py:80,175-177`). Per-vehicle 70/15/15 split (`federated.py:163-175`) and a separate IID global test set of 1,800 clean scenes balanced over region x weather and uniform over classes (`:223-234`).
- Default fleet (run, `configs/default.yaml`): 50 vehicles, 7,700 training samples in total, n_k 52-397 (median 138), 4 de-calibrated vehicles (ids 16, 21, 28, 45), link uptime 0.45-0.99 (mean 0.72), compute capability 0.37-1.76, local SGD steps per round tau_k = 10-65 even with fixed epochs (because of quantity skew), mean q_k 0.48 (calibrated 0.50, de-calibrated 0.26). Quality-aware weighting cuts the aggregate share of the 4 de-calibrated vehicles from 10.5% (size weights) to 5.5% (run).
- Real-dataset hooks are only documentation/stubs: `fedav/data/adapters.py:25-42,45-72` (KITTI/nuScenes/CARLA notes). No real data was ever run.
- The "sensor-health" signal q_k uses is computed from the simulator's own ground-truth context variables (weather label, calibration flag), not from image statistics: `fedav/data/scenes.py:78-99` `SceneContext.quality_score` (`1 - (0.45 blur + 0.30 occlusion + 0.20 rain_score)`, x0.55 if not calibrated). It is an oracle in the simulation.

**Model** (`fedav/models/perception.py`)
- `AVPerceptionNet` (`:83-173`): MobileNetV3-style stem + 3 stages of two inverted-residual blocks with squeeze-excite and Hardswish, GroupNorm everywhere (no BatchNorm; asserted by `tests/test_pipeline.py::test_model_contains_no_batchnorm`), 192-ch neck, 4x4 grid. Heads: centre heatmap -> softmax -> spatial soft-argmax for (cx,cy) (`:151-160`), size head (sigmoid), 6-way class head, trajectory head fed with [pooled, detached logits, detached centre] (`:171`). Parameter count 700,485 (run; cap 6M enforced `:128-133`).
- Loss `multitask_loss` (`:184-210`): CE + lambda_box(=1.0)*[2*SmoothL1(centre)+SmoothL1(size)] + lambda_traj(=0.5)*SmoothL1(trajectory), box/trajectory masked on background.

**One federated round** (`fedav/sim/runner.py:244-338`, `SimRunner.run`)
1. Select: `ClientSelector.select` (`fedav/server/selection.py:67-116`) picks S=ceil(0.3*50)=15 vehicles. Steps: sample predicted uptime = long-run uptime + N(0,0.08) jitter (`:57-64`); eligibility threshold 0.55, relaxed x0.7 repeatedly if too few eligible (`:72-81`); (1) "starved" eligible vehicles (unseen for >K=12 rounds or never seen) first, oldest first (`:83-88`); (2) region-bucketed round-robin ("trajectory-aware", `:92-104`; it only buckets by the region label, there is no trajectory/route model); (3) fill by `_score` = 0.55*uptime + 0.25*quality_signal + 0.10*log1p(n_k)/10 + 0.10/(1+times_selected) (`:118-123`).
2. Broadcast: `_broadcast` (`runner.py:129-161`): vehicles that held the previous-round model (tracked in `_last_sync`) get a global **delta**, others the full model; each group is one RSU multicast transmission when `comm.multicast` (byte counts from the actual serialiser).
3. Local training: `ClientTrainer.train` (`fedav/client/trainer.py:106-189`): E=5 epochs SGD (lr 0.01 cosine-decayed to 0 at the last round, momentum 0.9, wd 5e-4, grad-clip 5, batch 32), optional FedProx term (`:141-144`, default mu=0), delta = local - anchor (`:155-156`); optional sign-flip x6 attacker (`:192-199`); optional DP clip + Gaussian noise (`:160-169`); q_k computed on-vehicle (`:94-103`, `fedav/data/quality.py:59-73`).
4. Uplink: `TopKCompressor.compress` (`fedav/client/compression.py:39-50`): residual-corrected top-k (ratio 0.25) with on-vehicle error-feedback buffers; `UpdateSerializer.pack` (`fedav/client/serializer.py:43-58`): flatten, fp16, gzip(6), JSON header with CRC32; `SecureChannel.send_up` (`fedav/server/secure.py:158-168`): bytes + 34 B TLS overhead are billed, delivery is a Bernoulli(link_uptime) draw (so ~19% of selected vehicles drop; observed 12 of 15 report). Corrupt payloads rejected by CRC (`runner.py:193-199`). A straggler time-out exists (`:180-182`) but simulated durations (<= ~2 s) never approach the 45 s limit, so it never fires (`drop_straggler` = 0 in `runs_ingredient/momentum_only/rounds.jsonl`).
5. Aggregate: `FedAggregator.combine/apply` (`fedav/server/aggregator.py:87-140`): alpha_k = q_k n_k / sum_j q_j n_j (`fedav/data/quality.py:76-90`); optional FedNova normalisation `d = (sum alpha_k tau_k) * sum alpha_k dW_k/tau_k` when tau differ (`aggregator.py:95-101`); optional coordinate-wise weighted trimmed mean when >=4 updates and `byzantine_robust` (`:103-108`; `utils/tensors.py:98-115`), preceded by a 3x-median norm filter (`:150-169`); server momentum `v = beta v + d; applied = (1-beta) v + beta d` (`:117-129`, beta 0.9) — algebraically `applied = d + beta(1-beta) v_prev`; `w <- w + applied`. If `dp.secure_aggregation` (default **true**, `fedav/config.py:56`) and not Byzantine-robust, the aggregate is **replaced** by the masked-sum result (`runner.py:285-286`, see Q5 item 2).
6. Secure aggregation `SimRunner._secure_sum` (`runner.py:206-241`) + `SecureAggregationMasks` (`secure.py:43-100`): pairwise masks from SHA-256(secret:round:i:j) seeds, +mask for j>i and -mask for j<i, accumulated in float64, per-coordinate scale = 8 x (alpha-weighted mean update norm)/sqrt(numel) (`secure.py:92-100`); the runner checks every round that the recovered sum equals the plain weighted mean within 1e-3 relative and logs `secure_aggregation_verified`. The "secret" is `cfg.seed` (`runner.py:231`), a public config constant.
7. Convergence/eval: stop when ||w_{t+1}-w_t|| <= 1e-3 (`aggregator.py:175-179`) or R_max=60; evaluate on the global test set every round; keep the best-accuracy checkpoint (`runner.py:306-308`).

**Privacy and security features**
- DP (off by default): clip to L2 norm C=1 and add N(0, sigma^2) with sigma = z*C (`fedav/privacy/dp.py:53-71`); z calibrated by bisection so that R-fold composition of a Poisson-sub-sampled Gaussian under RDP (Mironov) is <= (eps=8, delta=1e-5) (`dp.py:104-173`); `PrivacyAccountant.client_sigma` splits noise as sigma/sqrt(|S|) across selected vehicles under secure aggregation (`dp.py:199-202`, used with `len(selected)` at `runner.py:166-169`); analytic Gaussian (Balle-Wang) bisection (`dp.py:74-101`). Validation figure: z=1.7482, eps spent 7.9963 at q=0.3, R=60 (`docs/figures/residuals.json: dp_composition`).
- Secure aggregation: see step 6; incompatible with trimmed-mean robustness (`README.md:232-235`); no dropout-recovery/Shamir (`README.md:612-614`).
- "No raw data egress": wire payload is the delta + 8 meta scalars (`tests/test_pipeline.py:179-190`); the fleet-reference label histogram is assembled in the clear in the simulator and the code says a deployment would need secure aggregation (`fedav/data/quality.py:11-19`, `federated.py:236-243`).
- TLS is a byte-cost model only (`secure.py:32-33,145-186`); `SecureChannel.handshake` is defined but never called (grep), so handshake bytes are not in MB/round.

**Evaluation protocol**
- Four arms on one fleet/seed: centralized (pooled data, 60 epochs), local-only (12 of 50 vehicles trained alone for 75 epochs = 60*5//4), "std FedAvg", "proposed" (`fedav/sim/benchmark.py:34-55`, `baselines.py:36-64,93-195`). Std FedAvg sends full fp32 weights, unicast, no compression, no momentum, no quality weights, no DP/secure agg (`baselines.py:52-64`).
- Metrics `fedav/metrics/evaluation.py:94-172`: global accuracy, balanced accuracy, macro-F1, "mAP@0.5" (one prediction per image; TP if class correct and IoU>=0.5; foreground classes only — not a COCO/KITTI-style multi-object detection mAP), ADE/FDE (normalised units), plus per-vehicle accuracy on each vehicle's **local test split** for dispersion/worst-client (`:194-209`).
- Acceptance checks of PRD 12.3 (`benchmark.py:87-175`): accuracy >= 90%, >=25% fewer rounds, >=30% less MB/round, MB/round <= 9, dispersion <= FedAvg, scale-free variants relative to 95% of the centralized ceiling, privacy (no egress).
- Ablation harness `fedav/sim/ablation.py:29-83` flips one switch at a time from the FedAvg config (selection, quality, momentum, adaptive epochs, all) plus DP, FedProx and Byzantine-attack extras. The extras (DP, FedProx, Byzantine) have **no committed outputs** (no `ablation.json` in `results/`).

**Other branches on the same (private) GitHub repo** (`git fetch`, `gh api`): `claude/determined-goldberg-vjp7i0` (2026-09-29) adds `python_prototype/fl_prototype.py` (numpy softmax-classifier FL demo, q_k = 1/(1+local loss), uptime-proportional selection, `--repeats` seeds) and `matlab_prototype/`, `docs/MODULES.md`; `claude/gracious-dijkstra-rd9z4g` adds a MATLAB linear-model sim; `claude/wonderful-dirac-75oqry` (2026-10-08) only corrects a stale README limitation (see Q5); `claude/optimistic-gates-54u939` adds Remotion agent skills (unrelated). The committed prototype `summary.csv` has `acc_std = 0.0000` for every arm, i.e. it was produced with one repeat.

### Inferences
- The system is best described as a high-fidelity *systems simulator* of known FL building blocks, not an algorithmic breakthrough; its value for a paper is the integrated, byte-accurate, reproducible testbed plus the (honest) negative/mixed findings.
- "Trajectory-aware" selection is a misnomer for region round-robin; "predicted uptime" is the ground-truth uptime plus noise. A patent specification would have to describe how these are obtained on a real fleet.
- Because q_k is computed from simulator ground truth, enablement for real vehicles (how to derive blur/occlusion/precipitation/calibration health from camera/LiDAR streams) is unspecified.

### Gaps
- The PRD (the real "specification" of the design) is absent; origin/author of the PRD requirements (quality-aware alpha_k, connectivity/trajectory selection, adaptive epochs) cannot be determined from the repo.
- No real-world dataset, no vehicle-hardware or radio measurements.

## Q2. Which components are novel vs standard, and what are the candidate inventive concepts (technical problem + technical effect) for claims?

### Takeaway
Nearly every ingredient is a published technique; the realistic patent angles are narrow combination/system claims (two-factor on-vehicle quality weight with a similarity floor; a gated-then-stratified-then-scored fleet scheduler; sync-state-aware delta/full multicast downlink; norm-matched float64 mask arithmetic) and, more promisingly, *not-yet-implemented* fixes for problems the repo itself exposed (tail-fairness interaction between selection and quality weighting; verifiable q_k). Current evidence of technical effect is weak (single seed, no synergy, tail regression), so claims would be exposed to obviousness rejections.

**Candidate inventive concepts (ranked by defensibility as implemented; claim-style wording is a drafting aid, not legal advice)**

*C1. Two-factor, on-vehicle quality weight with a "similarity floor" fused into size weights.* 
- Technical problem: under label/feature/quantity skew, vehicles with degraded sensors or corrupted labels pull the global model away; naive size weights over-trust large degraded shards, while a pure distribution-distance weight silences rare-but-clean regions.
- Features (code): q_k = clamp( [s_f + (1-s_f)(1-H(p_k,p_ref))] x health_k, q_min, q_max ), H = Hellinger distance between the vehicle's class histogram and a fleet reference, s_f=0.25 floor, health_k from onboard blur/occlusion/precipitation/calibration, q_min=0.05, q_max=1; only the scalar q_k and n_k are transmitted; alpha_k = q_k n_k / sum q_j n_j (`quality.py:59-90`, `trainer.py:94-103`).
- Draft claim sketch: "receiving from each of a plurality of vehicles a model update, a sample count and a scalar quality weight computed on the vehicle as the product of (i) a similarity term obtained by mapping a divergence between the vehicle's label histogram and a fleet reference histogram into a range bounded below by a non-zero floor and (ii) a sensor-health term obtained from onboard diagnostics comprising at least one of blur, occlusion, precipitation intensity and calibration status; clamping the product to a predetermined range; weighting the updates by the product of the sample count and the clamped quality weight, normalised over participating vehicles..."
- Technical effect (evidence): isolated at R=30: accuracy +2.0 pts over FedAvg control (70.78 -> 72.78), cross-client accuracy std 0.154 -> 0.106 (-31%), worst-client 22.4% -> 38.8% (`results/ingredients/ingredients.json`, `results/attribution/attribution.json`); aggregate share of the 4 de-calibrated vehicles halves (run). Single seed; +2.0 pts is within the README's own stated noise ("a point or two", `README.md:505-510`).
- Prior-art proximity: high for "quality/divergence weighting" in general; the floor + multiplicative sensor-health combination is a narrow differentiator. Assessment: low-to-medium.
- Weakness: in the combined R=60 run the worst-client accuracy is lower than FedAvg's (32.7% vs 46.3%) — see Q3/Q5.

*C2. Layered fleet scheduler: link-gate with progressive relaxation -> starvation-first promotion -> region-stratified round-robin -> composite score with freshness term.* 
- Problem: rounds stall on dropped V2I uplinks; discarding weak links biases coverage toward certain regions; some vehicles starve.
- Features: `selection.py:67-123` (uptime sample = long-run uptime + jitter; threshold 0.55 reduced by x0.7 until enough eligible; starved first; region buckets sorted by score; score 0.55 uptime + 0.25 quality + 0.10 size + 0.10 freshness).
- Draft claim sketch: "selecting a subset of S vehicles by (a) computing a predicted link uptime for each vehicle, (b) forming an eligible set of vehicles whose predicted uptime meets a threshold and repeatedly reducing the threshold by a multiplicative factor until the eligible set has at least S members, (c) first admitting vehicles of the eligible set not selected within K preceding rounds, (d) then admitting vehicles from region-specific queues in round-robin order ranked by a score combining predicted uptime, onboard sensor quality, data volume and a decreasing function of prior selections..."
- Effect (evidence): isolated at R=30: +8.2 pts (70.78 -> 79.00), std 0.154 -> 0.124, Gini 0.503 -> 0.454 (`ingredients.json`). The largest single effect in the study, but see caveats: (i) the *control's* selector is itself score-based and strongly link-biased, not random (Q5 item 3), so the +8.2 compares two link-aware selectors; (ii) components (threshold vs fairness guard vs stratification) were never ablated separately; (iii) reported/selected ratio did not improve (0.816 vs 0.824 per round, computed from the round CSVs), so the gain is not explained by fewer dropped uplinks; (iv) single seed.
- Documented defect: the starvation bound is **not** achieved (28 of 50 vehicles waited more than K=12 rounds; vehicle 26 (uptime 0.45) was selected once in 60 rounds; run). A claim of "bounded starvation" cannot be supported by the current implementation without a fix.
- Prior-art proximity: high (FedCS/Oort-style selection, age/staleness-aware scheduling, V2X-aware selection above). Assessment: low-to-medium as a combination.

*C3. Sync-state-aware delta/full downlink with RSU multicast accounting.* 
- Problem: vehicles that skipped the previous round cannot apply a delta; selection makes rounds a mixture.
- Features: RSU keeps a per-vehicle record of the last round whose model it holds; selected vehicles are partitioned into delta recipients (record = r-1) and full-model recipients; each group gets one multicast transmission (`runner.py:129-161`, `_last_sync` at `:118`).
- Effect: contributes to the 74.56 -> 8.72 MB/round reduction but is **not isolated** (only the cumulative stack in `docs/figures/08_communication_stack.png`: multicast removes 25.2 -> 8.0 MB; delta-vs-full effect not measured separately).
- Prior art: model-difference/delta broadcast is a general technique; the partition-by-sync-state detail may be less documented. Assessment: low; needs prior-art search.

*C4. Closed-loop uplink-budget controller with error feedback.* `BandwidthController` multiplicatively tightens top-k ratio by 0.7 when a round exceeds the MB budget and relaxes by 1.15 below 60% of budget (`compression.py:72-97`, `runner.py:304-305`). **Inert in the committed benchmark**: proposed arm MB/round ranges 7.35-8.92 (never above 9.0, never below 5.4), so neither branch can fire (`results/benchmark/proposed_fl/rounds.csv: mb_round`); the 9 MB budget is met by the initial ratio 0.25. Adaptive sparsification is published ([Han et al.](https://ar5iv.labs.arxiv.org/html/2001.04756), [FedSparQ](https://arxiv.org/pdf/2511.05591)). Assessment: low; no effect evidence.

*C5. Numerically exact weighted secure aggregation with norm-matched float64 masks and per-round verification.* 
- Problem found in repo: with real-valued pairwise masks accumulated in float32 and fixed scale 1.0 against converged updates (norm ~0.01), cancellation failed in 56 of 60 rounds (`git show f0f6ff4`, `docs/MATHEMATICAL_VALIDATION.md` section 6).
- Features: float64 accumulation, mask scale = 8 x per-coordinate update scale derived from the round's reported norms (`secure.py:51-100`), verification flag per round (`runner.py:241`). Measured max relative error 0.1816 (float32, scale 1) -> 6.76e-4 (float32, matched) -> 1.35e-7 (float64, matched); min mask:signal ratio 56.7x (`docs/figures/residuals.json: secure_aggregation`).
- Assessment: engineering fix; **security caveats make it unsuitable as a headline claim**: masks are real-valued with magnitude tied to the signal (not information-theoretic hiding as with modular masks), seeds derive from a public constant (`runner.py:231`), no key agreement, no dropout recovery, update norm is revealed. Low.

*C6. Compute-adaptive local epochs + normalised averaging* (FR-10): negative result (-12.2 pts alone; -6.2 with FedNova; `results/ingredients`, `results/fix/fix.json`), default off (`config.py:94`). Not patentable (FedNova is prior art; no benefit); publishable as a negative result.

*C7. System-level combination.* A claim to the whole pipeline (on-vehicle q_k + gated/stratified scheduler + weighted secure sum + EF-sparsified delta uplink + sync-aware multicast downlink + DP accountant) is the only way to protect the repo as built, but it is the most exposed to "obvious combination of known elements" objections, and the repo's own ablation shows anti-synergy at R=30 (`results/fix/fix.json: all_algorithmic_normalised` 68.17% vs control 70.78%; `results/attribution`: all-algorithmic 61.61%). The latter arms include adaptive epochs ON, and no matched R=30 arm of {selection+quality+momentum} with adaptive epochs OFF exists.

**Not implemented, but suggested by the repo's own findings (potential stronger inventive directions; must be implemented, tested and prior-art searched first)**
- O1. Selection-propensity-corrected quality weighting (importance weight q_k n_k / pi_k with pi_k the vehicle's realised selection frequency) or a joint selection-weighting rule, to remove the average-up/tail-down trade documented in `README.md:456-465` and `benchmark_report.md` (proposed worst-client 0.3265 vs FedAvg 0.4634). Importance-weighting under non-uniform sampling is a known idea in the FL sampling literature (my own knowledge, not searched here) so novelty depends on the specific coupling.
- O2. Tail-aware q_min/fairness controller: closed-loop adaptation of q_min or K to hold worst-decile accuracy (README names these levers as untuned, `README.md:464-465`).
- O3. Attested/verifiable q_k: q_k and n_k are self-reported scalars (`serializer.py` meta, `trainer.py:55-65`) and are not covered by the Byzantine experiment (the attacker flips the update sign but keeps an honest q_k, `trainer.py:192-199`), so a quality-inflation attack is an unaddressed vulnerability.
- O4. Secure collection of the fleet reference histogram that q_k needs (repo's own TODO, `quality.py:11-19`).

### Inferences
- The most defensible *existing* differentiators are C1's floor+sensor-health product and C2's layered pipeline with progressive threshold relaxation; neither is clearly novel. A patent drafter should treat the repo as an enabling disclosure of a combination and prioritise O1-O4 or any measured synergy as the claimable improvement.
- The repo's honest negative findings (adaptive epochs harm; tail regression; failed PRD criteria) are more valuable for a paper than for claims, and they give a clear "technical problem" statement for O1/O2.
- Whether any of this is "patent-ready" depends on counsel's prior-art search (the search here covered snippets of ~8 sources and one patent family only).

### Gaps
- No full-text patent search was done (USPTO/EPO/WIPO); the Toyota patent's claims on quality weighting are unconfirmed.
- Effect sizes for each concept are single-seed; no statistical significance exists for any of them.
- The delta/full downlink partition (C3) and the budget controller (C4) have no isolated measurements.

**A. Code and results problems (severity in brackets; "(run)" = reproduced by executing code)**
1.
